# Product Intelligence Onboarding

Read the canonical product page, current capabilities, active initiatives, requirements, GTM, and relevant parent context. Explain the product's purpose, users, strategy, boundaries, dependencies, and current work in plain language. Mark drafts, gaps, and stale or conflicting sources clearly.

Ask one focused question at a time only when it changes the learning path. Do not turn onboarding into a documentation-authoring session unless the user explicitly asks to fix a gap.
