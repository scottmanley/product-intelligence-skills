# Scout Wiki authoring contract

Use Scout Wiki as the canonical source for product documentation. Search before creating pages; fetch immediately before any update. Create substantive changes as drafts, validate every link, and ask a reviewer to set full width before publishing. Do not use YAML/front matter or duplicate visible metadata.

Product pages are concise current hubs. Create a child page only when it has its own lifecycle, owner, audience, or substantial content. Fold completed initiative outcomes into current requirements and GTM before retaining a concise history summary.
