# Support Answer

## Scout Wiki access

Use the installed **@Scout Wiki** plugin/app for every Wiki search and read. If it is not installed or connected, tell the user it is required and ask them to install or connect it before proceeding; accept page links/text only as a fallback. This skill does not install or connect plugins.

Find and read the canonical product, requirements, GTM, and active-initiative pages relevant to the question. Read the **At a glance** block on each relevant page. Lead with a plain-language answer suitable for the stated audience, then give a brief status context: the parent Product Status and the relevant Initiative, Requirement, or GTM Status. State when a required status is not documented; never infer it from the Wiki draft/published state. Distinguish confirmed current behaviour from drafts, plans, unknowns, or unsupported assumptions.

Never invent a policy, promise a delivery date, or give an explanation that the sources do not support. State the limitation and appropriate escalation owner when the documentation cannot answer safely.
